# 国际化（i18n）

> [English](I18N.md) · **简体中文**

FreeRemoteDesk 内置两种语言——简体中文（`zh-CN`）和英文（`en`）——并在两端的界面里都
提供了语言切换器。**没有引入任何第三方 i18n 库**：整套机制每个应用大约 100 行。

首次访问时使用的语言是**根据浏览器/操作系统的区域设置推断的**：`zh*` 区域会进入中文，
其余一律进入英文。用户在切换器里做出的明确选择会被保存，此后始终优先于推断结果。

## 哪些地方做了本地化

| 界面 | 文案所在位置 | 切换器 |
|---|---|---|
| PWA（浏览器客户端 + 落地页） | `pwa/src/i18n/{en,zh-CN}.ts` | `pwa/src/i18n/LanguageSwitch.tsx`，出现在连接页、配置页和落地页页脚 |
| Agent 窗口（Tauri WebView） | `agent/src/i18n/{en,zh-CN}.ts` | `agent/src/i18n/LanguageSwitch.tsx`，出现在「设置」页和主界面下方 |
| Agent 托盘菜单 + Rust 侧兜底文案 | `agent/src-tauri/src/i18n.rs` | 无——跟随已保存的语言，下次启动时生效 |
| 文档 | 每个 `*.md` 旁边的 `*.zh-CN.md` | 每个文档顶部的语言栏 |

以下内容**有意不做**本地化：线路协议的字段名与消息名、浏览器上报的 WebRTC 会话状态
（如 `connecting`）、设备品牌名（`iPhone`、`iPad`、`Mac`）、控制台/`log` 输出、原始的
诊断性报错文本（其中一部分由浏览器产生，例如 "Permission denied"，且代码会对其做字符串
匹配，翻译它等于改变行为），以及 `signaling/` Worker——它没有任何面向用户的文本。因此
Agent 的报错界面只本地化标题，原始报错信息原样显示在下方。

## 为什么这个模块是重复的两份

`pwa/src/i18n/` 和 `agent/src/i18n/` 是几乎相同的两份拷贝，这是刻意的。Vercel 把
`pwa/` 当作独立项目、用普通的 `npm install` 构建（见 [`DEPLOY.md`](DEPLOY.zh-CN.md)
与 `pwa/vercel.json`），因此它无法解析 `workspace:*` 依赖。若通过 pnpm workspace 共享
这个模块，部署就会挂掉。这个模块足够小，两份拷贝的代价远低于那个风险。

两份拷贝目前只有一处差异：Agent 的 `LanguageSwitch` 多接受一个 `onChange` 回调，用来把
选择同步进 Rust 配置；PWA 没有 Rust 侧，因此不需要它。

## 一次查词是怎么发生的

```
t(key, vars?)            → string     取译文，并替换 {name} 占位符
rich(text)               → ReactNode  渲染 **粗体** / *斜体* / `代码`
useI18n()                → { t, lang, setLang }   订阅语言变化
```

- `en.ts` 是键集合的唯一事实来源：`MessageKey = keyof typeof en`。
- `zh-CN.ts` 的类型是 `Record<MessageKey, string>`，所以**漏翻会在 `tsc` 阶段直接
  报错，而不是悄悄回退成英文**。`pnpm typecheck` 能抓到。
- 文案里可以嵌入一点极简的内联标记——`**粗体**`、`*斜体*`、`` `代码` ``——由 `rich()`
  转成对应元素。这样一句译文可以保持完整，而不必被拆成「一个片段一个 key」。这类字符串
  必须经过 `rich()` 渲染，不要直接输出。
- React 组件通过 `useI18n()` 订阅；非 React 模块（`pwa/src/savedHosts.ts`）直接 import
  `t` 做一次性取词。

## 持久化

| | PWA | Agent |
|---|---|---|
| 存储位置 | `localStorage["lang"]` | `localStorage["lang"]` **以及** agent 配置里的 `language` 字段 |
| 加载时以谁为准 | `localStorage` | 配置文件——agent 在 bootstrap 时会采用它，因为托盘菜单正是依据这个值构建的 |
| 首次运行 | 依据区域设置推断 | 依据区域设置推断，并在 bootstrap 时写回配置 |

在 Agent 里切换语言还会调用 `set_language` Tauri 命令，把 `language` 写入配置 JSON。
Rust 侧读取该值，用于托盘菜单以及唯一一处 Rust 生成的用户可见文案（`"Unknown device"`）。
Rust 看不到浏览器区域设置，因此它自身的兜底值是固定的 `"zh-CN"`
（`config.rs::DEFAULT_LANGUAGE`）；但 WebView 会在 bootstrap 时把推断出的语言持久化，
所以两者不一致的窗口仅存在于窗口打开前的首次启动。托盘菜单只在启动时构建一次，因此
**语言变更要到下次启动才会反映到托盘上，不是立即生效。**

两端都由 `main.tsx` 调用 `applyDocumentLang()`，让 `<html lang>` 与界面语言保持一致。

## 新增一条文案

1. 在 `en.ts` 里加上这个 key。
2. 在 `zh-CN.ts` 里加上同一个 key（忘了的话类型检查会告诉你）。
3. 使用 `t("your.key")`——如果文案含标记则用 `rich(t("your.key"))`。

两份字典都按界面用 `// ---------- 分节 ----------` 注释分组，请沿用这个分组方式。

## 新增一种语言

1. 把 `en.ts` 复制成例如 `ja.ts` 并翻译其中的值。
2. 在 `i18n/index.ts` 里注册——扩展 `Lang` 类型、加入 `DICTS`、并在 `LANGS` 里加一项
   （label 用该语言自己的写法，例如 `日本語`）。
3. 把它标注为 `Record<MessageKey, string>`，这样漏翻会在类型检查时报错。
4. Rust 侧需要在 `agent/src-tauri/src/config.rs` 的 `SUPPORTED_LANGUAGES` 里加上该
   语言标签，并在 `i18n.rs::tr` 里加一个分支。

其余地方都不用动：`readInitialLang()` 会用已知集合校验存储值，所以无法识别的标签只会
回退到默认语言，而不会让界面崩掉。

## 文档

每个 Markdown 文件都有一个简体中文姊妹文件，命名为 `<name>.zh-CN.md`（`README.md` →
`README.zh-CN.md`，`docs/DEPLOY.md` → `docs/DEPLOY.zh-CN.md`）。每个文件都在 H1 下方
带一行语言栏，指向自己的对应版本；译文内部的相对链接一律指向对应的译文文件。

**英文文件仍是正式版本。** 尤其是 `AGENTS.md`——它是用来粘贴给 AI 编程 agent 执行的，
而 README 里引用的那句安装提示词也是英文——编辑时请保持两者都能原样使用。本文档即定义了
这套约定：新增一个文档时，请一并新增它的 `.zh-CN.md` 姊妹文件与两端的语言栏。
